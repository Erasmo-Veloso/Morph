# Morph — Hackathon Demo

## Objective

Demonstrate the core concept in approximately two minutes.

The demo must make the transformation of the smartphone visually obvious.

---

## Scenario

Lesson:

**Physics — Accelerated Motion**

Teacher's intention:

> Teach accelerated motion with a short explanation, a practical experiment, analysis of results and reflection.

---

## Demo Flow

### 01 — Compile

Teacher enters the lesson intention.

Click:

```text
COMPILE
```

Result:

```text
UNDERSTAND
MEASURE
ANALYSE
REFLECT
```

---

### 02 — Start

Teacher clicks:

```text
START
```

Android receives the Capsule.

Current state:

```text
UNDERSTAND
```

---

### 03 — Morph

Teacher clicks:

```text
NEXT
```

Android changes to:

```text
MEASURE
```

The accelerometer becomes available.

Show real sensor data.

---

### 04 — Analyse

Teacher clicks:

```text
NEXT
```

Android changes to:

```text
ANALYSE
```

Show collected data/graph.

---

### 05 — Offline

Disable Internet.

The lesson must continue.

Show:

```text
LOCAL MODE
```

The active policy remains valid.

---

### 06 — Integrity

Trigger a defined integrity/restriction event.

Dashboard receives an event from the device.

Example:

```text
Integrity event detected
State: NON-COMPLIANT
```

---

### 07 — Recovery

Restore Internet.

Queued events synchronize.

Show:

```text
3 queued events synchronized
```

---

### 08 — End

Continue to:

```text
REFLECT
```

Then:

```text
END
```

---

## What the Jury Must Understand

Within the first part of the demonstration, the jury should understand:

1. The teacher describes the lesson.
2. Morph compiles it.
3. The lesson becomes executable.
4. The smartphone changes capabilities according to the pedagogical phase.
5. The lesson continues offline.
6. Integrity can be verified without turning the product into surveillance.

---

## Demo Principle

Do not explain the concept for five minutes before showing it.

Show the transformation first.

```text
Intent
→ Compile
→ Morph
→ Offline
→ Integrity
```
